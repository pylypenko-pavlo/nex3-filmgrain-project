================= WHAT IS SOLID (VERIFIED) =================
1) Fsys I/O prototypes (from libInfraFsys debug format strings):
   Fsys_Open  @0x143fd  int  Fsys_Open(const char* path, void** outHandle, unsigned long flags)
   Fsys_Close @0x11d01  int  Fsys_Close(void* handle)
   Fsys_Read  @0x150d1  long Fsys_Read(void* h, void* buf, unsigned long len)
   Fsys_Write @0x16cd9  long Fsys_Write(void* h, const void* buf, unsigned long len)
   Fsys_Seek  @0x15ecd  int  Fsys_Seek(void* h, long long off, int whence, long long* outpos) [64-bit]
   Fsys_Rename@0x1593d   Fsys_Remove@0x154b9   Fsys_Stat@0x167bd
   Resolve via __dlopen("libInfraFsys.so",1)+__dlsym. Paths are Fsys "A:\DCIM\...\DSC*.JPG"
   namespace -> raw open() fails; read the whole JPEG by looping Fsys_Read to EOF (gives srcSize).

2) FRESH-CAPTURE GATE = "handle was WRITTEN" (no flag decoding, robust):
   Fsys_Open records handle->path for DCF-JPGs; Fsys_Write marks the handle written; Fsys_Close
   processes ONLY if (DCF-JPG) AND (written) AND (path not in an 8-entry recently-done ring). A
   re-read/thumbnail opens read-only + only Fsys_Read -> never marked -> skipped. Idempotent.
   => fires exactly once on the fresh full-res save (solves 4a's "every close / multiple per file").

3) FAIL-SAFE (absolute, by construction):
   - Fsys_Close calls the REAL close FIRST, returns its value UNCHANGED; roundtrip runs AFTER and
     only delays our return by the codec time.
   - Original JPG untouched until a COMPLETE, SOI-valid re-encoded JPEG exists; writeback goes to a
     ".TMP" path and only a full successful write is Fsys_Rename'd atomically over the original.
   - ANY failure (resolve NULL / mmap NULL / open/read/decode/encode/write error / short write /
     bad SOI / bad w,h) -> original UNTOUCHED, temp removed, all mmaps munmap'd.
   - No recursion (roundtrip calls the RESOLVED real Fsys_*, and ".TMP" isn't a DCF-JPG).

4) ALLOCATION: raw mmap(MAP_ANON), freed on every exit. src=16MB (JPEG bytes), pix=W*H*2 (4:2:2
   assumption, SEE BLOCKER), enc=16MB. W,H from the SOF0 marker (SOI-anchored parse_wh()).

================= KEY STRUCTURAL FACT =================
THE DECODE->ENCODE ROUNDTRIP CANNOT BE TESTED IN ISOLATION. The updater is a recovery Linux with
NO imaging stack (liro/av-cam can't start; SA-DSP regs not ARM-mapped, C-SYS-006); /dev/ldec is a
node but the HW codec isn't brought up; MprLib is initialized by the appFw. qemu has no HW codec
and doesn't emulate the ldec/DMA ioctls. => DecodeStillOnMemory/EncodeStillOnMemory ONLY FUNCTION
inside the booted appFw. The isolation/qemu harness validates EVERYTHING ELSE (load, Fsys+codec
symbol resolution non-null, the gate, a fake-Fsys read/write round, SOF parse, mmap, temp+rename,
fail-safe, timing plumbing) -> the roundtrip itself is BOOT-tested. The fail-safe makes that first
boot test safe: codec no-op/junk -> original JPG never touched. Codec time measured on-camera via
gettimeofday() timers -> logged "4b: ROUNDTRIP ok dec_us=.. enc_us=.. bytes=..".

WRITE+CREATE+TRUNC value (ideally read verbatim from the appFw call site that creates DSC*.JPG).

OTHER NOTES (not brick-blocking):
- pix=W*H*2 hardcodes 4:2:2; if the decoder outputs another format the dst may be too small
  (overflow) -> part of BLOCKER 2 (decoder output format).
- roundtrip SYNCHRONOUSLY delays the Fsys_Close return by dec+enc time -> may stall the save-path
  UI; acceptable for the 4b measurement (that's exactly what dec_us/enc_us capture), async later.
- Burst (two concurrent JPG saves) races the shared static Mcmd state; single-shot test avoids it.

  reversing. DEFERRED to 4c per owner decision; not used in 4b.

================= CRASH ROOT-CAUSED (2026-10-20, static disasm) — it's the BUFFER, not our call =================
[VERIFIED] CALLING CONVENTION WAS CORRECT: all Set*OnMemory handlers are static-style (prologue mov r4,r1;
GOT globals; argc guard cmp r0,#N; NO [r0+off] this-deref) => r0=argc, r1=argv, our fn(argc,argv) was right.
Decode/EncodeStillOnMemory ignore args and load the MprIf instance from a GOT global (mp_mprIf, set by
MprIfMcmd::SetInstance @0x5d4909 at appFw init). DispParam @0x5d5918 is a `movs r0,#1; bx lr` NO-OP stub
(skipping it was correct). So the this/argc and DispParam theories are RULED OUT.
[VERIFIED] THE Mcmd on-memory path is a DEBUG path: the Set*OnMemory names appear ONLY in the Mcmd
command-name table (strings @0xdbcf-0xde05), reachable from the MPR text console (testcmd/sndcmd), NEVER
from the normal capture/save. Copying it does not replicate the firmware.
[VERIFIED allocators; strong-inference causation] THE CRASH = PIXEL BUFFER. The codec operates on DMM-pool
buffers (physically-contiguous / DMA-coherent, from the reserved imaging DRAM pool, A-MEM-003). Allocators:
mcmn_dmm_alloc/mcmn_dmm_free (libInfraMediaCommon @0x94cd/@0x9739, imported by libObj); dmm_alloc(size,u16*)
(libsencore @0x135c5); DmmAccess::DmmAllocate (libmprctrl @0x19d71) + GetExtAdrsFromDmmAlloc (@0xc89f,
handle->VA). The codec param "VirtAddr" is a VA INTO the DMM-mapped region (which carries the bus/physical
address the HW codec DMAs to). Our mmap(MAP_ANON) VA = scattered physical pages, no bus mapping => the HW
codec's DMA (ioctl DMA_TRANSFER_MEM / IOCTL_CMD_SET_PHYS_) hit a bogus physical address => SIGSEGV. That is
exactly the boot-test crash.
[VERIFIED] STRUCT API MprIf::EncodeStill @0x16f4b7 / PlayStillImage @0x16ff81 are NON-static members (need a
MprIf instance, obtainable) and STILL require MPR::BufferArea (DMM) buffers — cleaner return/out-size + no
shared-static race, but it does NOT remove the DMM-buffer requirement (the real crash).

=> THE STRATEGIC FORK (codec approach for the grain shim):
  OPTION 1 [agent-recommended] SELF-CONTAINED SOFTWARE JPEG decode->grain->encode embedded in the shim:
    pure CPU, plain mmap buffers, NO DMM / NO HW codec / NO DMA / NO imaging-pool contention. Sidesteps the
    exact crash. BIG WIN: fully testable OFF-CAMERA in qemu on the REAL DSC09787.JPG (the HW path can't be).
    Cost: ~800-1500 lines freestanding baseline-JPEG codec (or adapt a compact single-file decoder+encoder),
    ~1-3 s per 16 MP save. Design items: preserve EXIF/APP1 (+APP2/MPO) by splicing the original's APPn
    segments after SOI; grain = luma plane only (matches the film-grain goal with precise spatial control).
  OPTION 2 HW codec + DMM buffers + struct API: reuse Sony's fast codec; resolve mcmn_dmm_alloc, allocate

  OPTION 3 DCT-coefficient-domain grain: entropy-decode -> perturb luma DCT coeffs -> entropy-recode (same
    tables). Much less code than a full SW codec, fast, no HW/DMM, off-camera testable; but frequency-domain
    grain is coarser / quantization-limited / blockiness risk vs precise spatial grain.
